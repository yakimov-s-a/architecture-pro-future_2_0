# Интеграция с CI/CD и удаленным хранением состояния

## Удаленное хранение состояния

Ключевые решения:

- Состояния окружений изолированы друг от друга, ошибка в dev не может повредить prod;
- Ни один секрет не хранится в `backend.tf`, учетные данные для доступа к S3 передаются через переменные окружения
  CI/CD, а не через `-backend-config` файлы в Git;
- Локальный `terraform.tfstate` никогда не создается и не коммитится — путь исключен в `.gitignore`.

## CI/CD-пайплайн

| Этап       | Когда запускается      | Что делает                                                                                               |
|------------|------------------------|----------------------------------------------------------------------------------------------------------|
| `validate` | На каждый pull request | `terraform init -backend=false` + `terraform validate` для всех окружений                                |
| `plan`     | На каждый pull request | `terraform init` + `terraform plan` для dev / stage / prod по отдельности, план сохраняется как артефакт |
| `apply`    | Вручную, по кнопке     | `terraform init` + `terraform apply -auto-approve` для выбранного окружения                              |

Все переменные из защищенных CI/CD-переменных GitLab с префиксом окружения.

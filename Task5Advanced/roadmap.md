# Стратегический роадмap внедрения Data Mesh

## Ключевые роли Data Mesh

| Роль                                      | Зона ответственности                                                                                       | Этапа появления                                                    |
|-------------------------------------------|------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------|
| Data Product Owner                        | Владеет контрактом доменных данных как продуктом; приоритизирует backlog доменной витрины                  | Пилот (0-6 мес.) — по 1-2 доменам, далее все домены                |
| Data Engineer (доменный)                  | Реализует потоковые трансформации, поддерживает витрину домена, обеспечивает соответствие схеме в каталоге | Пилот (0-6 мес.)                                                   |
| Platform Engineer (платформенная команда) | Поддерживает событийную шину, каталог схем, self-service портал как общую инфраструктуру для всех доменов  | Пилот (0-6 мес.)                                                   |
| BI-аналитик                               | Строит отчеты и дашборды в портале самообслуживания в рамках своего домена                                 | Расширение (6-18 мес.), когда витрины покрывают другие домены      |
| Data Governance Lead                      | Контролирует стандарты качества данных, RBAC, соответствие регуляторным требованиям через все домены       | Расширение (6-18 мес.)                                             |
| Domain Architecture Owner                 | Отвечает за bounded context домена, следит за отсутствием утечки бизнес-логики обратно в DWH / Camel       | Финализация (18-36 мес.), постоянное владение целевой архитектурой |

## Роадмап по этапам

### Пилот

- **Горизонт:** 0-6 мес.
- **Ключевые активности:**
    - выбор 1-2 доменов (фин. расчеты, пациентский поток);
    - внедрение каталога схем и DLQ;
    - запуск первой доменной витрины как data product;
    - обучение первых Data Product Owner и Data Engineer.
- **Вовлеченные роли:**
    - Data Product Owner;
    - Data Engineer;
    - Platform Engineer.
- **Привязка к бизнес-целям:**
    - архитектурное решение сформировано и согласовано;
    - в доменах запланированы проекты по развитию витрины данных.

### Расширение

- **Горизонт:** 6-18 мес.
- **Ключевые активности:**
    - подключение критических доменов (Fintech, AI Diagnostics, HR/Inventory) как data products;
    - запуск потоковых витрин по каждому домену;
    - внедрение ACL для Camel / DWH;
    - появление BI-аналитиков в self-service портале;
    - формализация Data Governance.
- **Вовлеченные роли:**
    - Data Product Owner;
    - Data Engineer;
    - BI-аналитик;
    - Data Governance Lead.
- **Привязка к бизнес-целям:**
    - реализован портал самообслуживания;
    - бизнес-пользователи в доменах могут работать с данными в рамках новой архитектуры.

### Масштабирование и поддержка доменов

- **Горизонт:** 18-36 мес.
- **Ключевые активности:**
    - отказ от точечных синхронных интеграций на критическом пути;
    - полный переход на доменную аналитику по потокам;
    - подключение новых доменов при выходе на новые продукты / регионы (фармацевтика, электроника, новые рынки);
    - переход от batch к near-real-time во всех доменах.
- **Вовлеченные роли:**
    - Domain Architecture Owner;
    - полный состав ролей во всех доменах.
- **Привязка к бизнес-целям:**
    - масштабирование по продуктам, географии и данным;
    - слабосвязанная событийная платформа.
